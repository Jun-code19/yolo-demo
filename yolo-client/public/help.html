1. 系统概述

智能视频分析系统是一个集视频监控、目标检测、人群分析于一体的综合管理平台。系统采用先进的AI算法，支持多种设备类型和检测模式，为用户提供全方位的视频监控解决方案。

待补充截图 images/help/overview.png
图1.1 系统首页
核心功能模块：
  • 首页：设备、事件、性能等概览统计
  • 目标检测：实时检测、检测配置、检测事件
  • 人群分析 / VLM 巡检 / 规则引擎：区域统计、大模型巡检、复合告警
  • 视频设备 / 模型管理：摄像头接入、YOLO 本地模型与 VLM 大模型
  • 推送配置 / 监听·订阅：对外推送、外部事件接入
  • 边缘节点 / 系统管理：分布式节点、日志、地图配置、设备探活
  • 数据大屏：顶部栏入口，展示 KPI、热力图、规则告警与外部接口数据

3.2 检测配置

侧栏「目标检测 → 检测配置」
待补充截图 images/help/detection-config.png
图3.2 检测配置页面
选择要配置的设备
设置检测参数：
  • 检测区域：可以设置检测范围
  • 目标类别：选择需要检测的目标类型
  • 灵敏度：调整检测的灵敏度
  • 保存模式：选择检测结果的保存方式
检测参数影响说明：
  • 灵敏度：影响目标检测的敏感程度。灵敏度越高，越容易检测到微小或不清晰的目标，但也可能增加误报。建议根据实际场景和需求进行调整。
  • 置信度阈值：表示检测结果的可信度。只有当检测目标的置信度高于此阈值时，才会被认为是有效目标。提高阈值可以减少误报，但可能漏报一些真实目标。
目标类别示例：
  • 系统支持检测多种预设目标类别，例如：**人、车辆、自行车、宠物**等。部分模型还支持更细致的分类，如不同类型的车辆。用户也可以根据实际应用场景，通过自定义模型来扩展或定制需要检测的目标类别。
点击"保存"按钮完成配置

4. 人群分析

4.1 创建分析任务

侧栏「人群分析」
待补充截图 images/help/crowd-analysis.png
图4.1 人群分析页面
点击"新建任务"按钮
选择要分析的设备
设置分析参数，包括检测类别、时间间隔等
点击"确认"按钮创建任务
分析参数详情：
  • 检测类别：选择需要进行人群分析的目标类型（如"人"）。系统将只对选定类别的目标进行计数和分析。
  • 时间间隔：设置数据统计和分析的时间粒度（如5秒、1分钟）。更短的时间间隔可以提供更实时的趋势数据，但可能增加系统负担；更长的时间间隔则提供更宏观的趋势。

4.2 查看分析结果

在任务列表中找到要查看的任务
待补充截图 images/help/view-results.png
图4.2 查看分析结果页面
点击"查看结果"按钮
查看分析结果，包括人数统计、趋势图等
提示：系统支持设置预警阈值，当人数超过阈值时将自动发送预警信息。
典型应用场景：
  • 区域人流密度监控：实时监测特定区域（如商场出入口、公共广场）的人员密度，避免过度拥挤。
  • 滞留预警：对在特定区域长时间停留的人员进行预警，适用于安全监控。
  • 人员轨迹分析：分析人员在区域内的移动路径和热点区域，优化空间布局。
  • 客流量统计：统计不同时间段的客流量，为商业决策提供数据支持。

5. VLM 巡检

VLM 巡检使用视觉大模型对摄像头定时截图分析，识别火情、违规等场景，结果可用于规则引擎与数据推送。

5.1 巡检任务

进入左侧菜单「VLM 巡检」
待补充截图 images/help/vlm-inspection-task.png
图5.1 VLM 巡检任务
点击「新建任务」，配置摄像头、Cron 调度、VLM 模型与提示词
在任务中设置 告警标签（alert_labels），供规则引擎按标签匹配
启用任务后，系统按调度自动截图并调用大模型分析
提示：规则引擎中选择「VLM 巡检」条件时，需指定巡检任务；标签可多选，任一命中即可。

5.2 巡检结果

待补充截图 images/help/vlm-inspection-findings.png
图5.2 VLM 巡检结果
在任务详情页查看历史截图与分析结论
仅 needs_alert = true 的结果会进入规则评估（可在规则条件中勾选「仅告警」）
巡检发现会作为 VLM 事件源参与复合规则匹配

6. 规则引擎

侧栏「规则引擎」含「规则列表」「命中记录」两个页签。由 detect-server 周期性评估，命中后落库并按推送标签向外推送。

6.1 规则列表

「规则列表」页签 → 点击「新建规则」
待补充截图 images/help/alert-rule-list.png
图6.1 规则列表
填写名称、优先级、推送标签（与推送配置的 tags 对应）
基本设置 · 设备：留空表示监听全部设备；指定后仅拉取该设备事件
匹配逻辑：
  • 全部满足（AND）：窗口内所有条件都命中才告警
  • 任一满足（OR）：无需时间窗口，任一条件有新命中即告警
  • 同设备：开启时多条件须在同一摄像头；关闭可跨摄像头组合
  • 窗口 / 冷却：AND 模式扫描最近 N 秒；冷却为命中后 N 秒内不重复告警

6.2 触发条件

待补充截图 images/help/alert-rule-conditions.png
图6.2 规则触发条件
支持四类事件源：
  • VLM 巡检：选任务 + 告警标签，可勾选「仅告警」
  • 检测事件：三种匹配方式
    • 子事件类型：人数增减、越线、离岗等智能分析子事件，即时命中
    • 目标类别/数量：按检测框类别与数量（≥、= 等），可设「持续 N 秒」
    • 持续不在 (NOT)：目标持续不在达到 N 秒后告警
  • 外部监听事件：来自数据监听器的外部平台事件
  • 事件订阅：绑定订阅方案与事件类型
注意：「持续」仅对检测事件的「目标类别/数量」和「持续不在」有效；VLM、监听、订阅、子事件类型均为即时命中，无需设置持续。

6.3 命中记录

待补充截图 images/help/alert-rule-hits.png
图6.3 规则命中记录
「命中记录」页签查看复合告警
可查看匹配事件快照、涉及设备、规则定义快照
支持确认 / 忽略处理；数据大屏的「规则告警」统计与此同源
排查不命中：确认 detect-server 已启动；检测类子事件需 scenario_type / label 与上报一致；人数增减等需智能分析任务正常运行。

7. 视频设备

侧栏「视频设备」用于管理摄像头、NVR 等接入设备，是检测、巡检、订阅等功能的基础。

支持的设备类型：网络摄像头（RTSP/HTTP/ONVIF）、NVR 多通道、边缘节点等。

7.1 添加设备

侧栏「视频设备」，点击「添加设备」
待补充截图 images/help/device-list.png
图7.1 视频设备列表
填写设备 ID、名称、类型、IP、端口、用户名/密码等
NVR 需配置通道号与码流类型（主码流/子码流）

7.2 编辑设备

7.3 删除设备

点击「删除」并确认；将同时清除相关检测配置与历史事件，不可恢复

7.4 设备状态

列表显示在线/离线/异常状态；可在「系统管理 → 设备监控」配置探活策略

14. 常见问题

14.1 设备连接问题

检查设备IP地址和端口是否正确
确认用户名和密码是否正确
检查网络连接是否正常
确认设备是否支持RTSP协议
查看设备连接日志获取详细错误信息
参考：详见 7. 视频设备 章节。
常见错误：
  • 连接超时：检查网络连通性和防火墙设置
  • 认证失败：确认用户名密码正确
  • 协议不支持：确认设备支持所选协议

14.2 检测问题

确认已选择正确的检测模型
检查视频流是否正常播放
调整检测参数（如灵敏度、置信度阈值）
检查检测区域设置是否正确
确认目标类别配置正确
查看检测日志分析问题原因
检测优化建议：
  • 根据场景选择合适的模型
  • 调整检测区域避免干扰
  • 设置合理的置信度阈值
  • 定期更新和优化模型
参考：欲了解更多目标检测信息，请参阅3. 目标检测章节。

14.3 规则引擎问题

确认 base_detect_server.py 已启动（规则评估不在 data-server 运行）
检查规则是否启用、推送标签是否与推送配置匹配
检测子事件不命中：核对 scenario_type、label 与检测任务实际上报是否一致
OR 规则：仅处理上次评估后的新事件；AND 规则：注意窗口秒数与各条件「持续」设置
跨设备组合：需关闭「同设备」；单摄像头规则可指定基本设置中的设备
参考：详见 6. 规则引擎 章节。

15. 附录

15.1 词汇表

NVR
网络硬盘录像机（Network Video Recorder），用于录制和存储IP摄像机视频流的设备。
RTSP
实时流协议（Real-Time Streaming Protocol），一种用于控制流媒体的协议。
ONVIF
开放网络视频接口论坛（Open Network Video Interface Forum），一个全球性的开放标准，旨在促进IP物理安全产品的标准化通信。
YOLO
You Only Look Once，一种流行的实时目标检测算法。
NMS
非极大值抑制（Non-Maximum Suppression），在目标检测中用于消除重复的检测框。
复合告警 / 规则引擎
将多源事件（VLM、检测、监听、订阅）按 AND/OR 逻辑组合评估，命中后生成告警记录并推送。
VLM 巡检
使用视觉大模型对摄像头定时截图分析，输出结构化标签与是否告警标志。
推送标签（push_tags）
规则与推送配置之间的关联键；规则命中时，匹配相同 tags 的推送配置才会收到消息。
MQTT
消息队列遥测传输（Message Queuing Telemetry Transport），一种轻量级的消息协议，适用于物联网设备。
